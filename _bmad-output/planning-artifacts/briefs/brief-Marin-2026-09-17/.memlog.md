Primærbrukere: driftsledere og fiskehelseansvarlige. Datakilder: historiske lusetall (BarentsWatch/Mattilsynet), vanntemperatur, sesongmønster.
- (decision) Form-faktor: hovedsakelig web/dashboard, men fortsatt åpent for justering. Teknisk løsning/stack: ikke diskutert med Ella ennå, fortsatt åpent. Omfang: konseptuell demo med syntetiske/historiske data, ikke nødvendigvis live BarentsWatch API-integrasjon i første versjon.
- (decision) Fred vil fortsette raskt ('bare gå videre') fremfor å samle mer input nå - resterende detaljer (kursoppgave, konkurrenter, modell-ambisjon) fylles inn senere i prosessen. Velger fast path: kladd med [ASSUMPTION]-tagger, review og iterasjon etterpå.
- (event) Research: Lakselusforskriften (FOR-2012-12-05-1140) krever <0.5 voksne hunnlus/fisk i snitt, strengere <0.2 i Midt-Norge og sørover uke 16-21. BarentsWatch Fiskehelse har åpent API med historikk tilbake til 2012, ukentlig rapportering fra oppdretter til Mattilsynet. Fant beslektet åpen kildekode-prosjekt 'Dr-grimen/oppdretter' på GitHub (varselsystem for lakselus/sykdom/soner fra åpne kilder) - observasjonsverktøy, ikke prediktivt. Relevant for differensiering.
- (event) Kladd av brief.md og addendum.md skrevet (fast path, [ANTAGELSE]-tagger for åpne punkter). Klar for gjennomgang med Fred.
